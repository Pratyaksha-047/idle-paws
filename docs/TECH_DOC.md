## 1. What it is

Idle Paws is a **Claude Desktop extension** that adds:

1. **A pixel pet** (cat, dog or duck) that lives *on top of Claude Desktop's window*, standing on the prompt input box. It walks, sits, sleeps, plays fetch, can be dragged, and follows the mouse if asked.
2. **Reactions to Claude Code**: when a Claude Code session finishes, the pet hops and says *"Done! · project"*; when Claude needs the user, it shows *"!"* and *"Claude needs you"*.
3. **Mini games** (2048, Sudoku, Minesweeper, Snake, Tetris) served from localhost and opened in Claude Desktop's built-in **browser pane**, so you can play while Claude works.

The main constraint: Claude Desktop has **no plugin UI API**. An MCP extension can only expose tools; it cannot draw on Claude's window. Idle Paws works around this with a separate native macOS app that:
- draws a transparent, click-through window aligned with Claude's window,
- reads Claude's UI through the **macOS Accessibility (AX) API** to find the prompt box,
- drives Claude's browser pane through AX to open games without needing a Claude turn.

### Why a separate app instead of doing everything in node?
- **Drawing over another app's window** needs AppKit (`NSPanel`, window levels, click-through).
- **Accessibility permission is granted per app.** Putting AX in its own signed bundle means the grant covers only Idle Paws, not `node` or Claude.
- **One overlay, many clients.** Desktop and Code may both start the MCP server; they share one overlay through the socket.

## 4. Components in detail

### 4.1 MCP server — `server/index.js`

Hand-written MCP over stdio (no SDK). Newline-delimited JSON-RPC 2.0.

| Method | Behaviour |
|---|---|
| `initialize` | echoes client `protocolVersion` (default `2025-06-18`), advertises `tools` |
| `ping` | `{}` |
| `tools/list` | 5 tools below |
| `tools/call` | dispatch; errors come back as `isError` text results, not JSON-RPC errors |
| `notifications/*` | ignored |
| other | `-32601 Method not found` |

**Tools**

| Tool | Args | Overlay cmd | Result |
|---|---|---|---|
| `open_game` | `game?` ∈ `2048,sudoku,minesweeper,snake,tetris` | `open_game` | localhost URL + instruction for Claude to open it in the browser pane |
| `open_console` | – | `console` | "Console opened next to the pet." |
| `pet_show` | – | `show` | "Pet is visible." |
| `pet_hide` | – | `hide` | paw print remains |
| `pet_status` | – | `status` | JSON: `petVisible`, `claudeWindow`, `floorSource`, `accessibilityTrusted`, `gamesUrl` |

**Overlay link**
- `connect({launch})`: tries the socket. If that fails: `chmod 755` the binary, strip `com.apple.quarantine` (the `.mcpb` unzip can quarantine it), `open -g IdlePaws.app`, then retry every 250 ms for up to 10 s.
- When connected it sends `{"id":0,"cmd":"hello","args":{"client":"desktop|code"}}`. This takes a **lease** that keeps the app alive.
- `request(cmd)`: refuses if Claude Desktop isn't running (checked with `ps -axo comm=`). 4 s timeout per request. Replies are matched by `id` in a `pending` map. On socket close, all pending requests are rejected.
- `keepAlive()` runs every 10 s: if Claude Desktop is running and there's no socket, it relaunches the overlay (crash recovery).
- Env: `IDLE_PAWS_CLIENT` (`desktop` via manifest / `code` via `claude mcp add`), `IDLE_PAWS_APP` (override app path).

### 4.2 Claude Code hook — `server/hook.js`

- Registered for `Stop` → `done` and `Notification` → `attention`.
- Reads hook JSON from stdin (`hook_event_name`, `cwd`) and sends a single `react {kind, project: basename(cwd)}` line to the socket.
- **Never blocks Claude:** hard 1 s budget, always exits 0, and swallows socket errors (no overlay running = no-op).
- Installed by `scripts/install-hooks.mjs`, which is idempotent: it removes any group whose command contains `idle-paws` or the legacy `claude-pets`, then appends one. It writes a `settings.json.bak-idle-paws` backup first. `--remove` uninstalls.
- Chat-tab conversations in Claude Desktop have no hooks, so only Claude Code triggers reactions.

### 4.3 Native app — `AppController`

Startup sequence (`applicationDidFinishLaunching`):
1. **Single instance.** If connecting to `pets.sock` succeeds, another instance is live, so this one exits 0.
2. Start `ControlServer` (unlinks a stale socket, binds, `chmod 600`).
3. Start `HTTPServer` on the first free port in `4747…4766`.
4. Create the `Overlay` and start `WindowTracker`.
5. Timers: `refreshFloor` every 250 ms; `checkLifecycle` every 5 s.
6. Observe `didTerminateApplication` → quit when Claude Desktop quits.
7. Global `leftMouseDown` monitor → `outsideClick` to the web layer (closes the console).
8. Prompt for the AX grant **once** (`prefs.axPrompted`).

**Lifecycle rules** (disabled when `IDLE_PAWS_DEV=1`):
- Claude Desktop not running → terminate.
- `leaseCount == 0` for more than 20 s → terminate. Leases are held by MCP server connections. A hook connection does not send `hello`, so it does not keep the app alive.

**Floor computation** (`applyFloor`): the floor is the line the pet stands on, in window-local coordinates.

| AX state | Prompt found | Floor |
|---|---|---|
| trusted | yes, composer card | `card.minY` (pad 0), x-span = card |
| trusted | yes, bare text area | `input.minY − floorPad(14)` |
| trusted | no | `nil` → **pet hides** (prompt covered by a dialog or settings page). There is a 300 ms grace period against flicker. |
| not trusted | – | fallback: `height − floorOffset(150)`, x 24…width−24, `source:"offset"` |

When anything changes, `pushEnv()` sends `{width, height, gameBase, floor}` to the web layer, deduplicated by string key.

**Command handling** (from socket):

| cmd | Action |
|---|---|
| `show` / `hide` / `console` | forwarded to the web layer as `command` |
| `open_game` | returns the URL only; Claude opens it via its own browser tool |
| `play` | `BrowserPaneOpener` opens the URL itself (no MCP tool uses this today; the web console posts `openGame` instead) |
| `react` | forwarded to the web layer as `react` |
| `status` | status snapshot |

### 4.4 `ControlServer`

- Unix domain socket, `SOCK_STREAM`, backlog 16, mode `0600` (only the current user).
- One detached thread per connection; reads lines with a blocking `LineReader` (1 MB line cap).
- Protocol: request `{"id":N,"cmd":"…","args":{…}}\n` → reply `{"id":N,"ok":bool,…}\n`.
- Commands run on the **main thread** (`DispatchQueue.main.async`). Replies are written under an `NSLock` per connection, with `SO_NOSIGPIPE`.
- `hello` increments `leaseCount` once per connection; disconnect decrements it.

### 4.5 `WindowTracker`

- Finds Claude by bundle ID `com.anthropic.claudefordesktop`.
- `CGWindowListCopyWindowInfo(onScreenOnly)`: first window owned by Claude's PID with layer 0, size ≥ 400×300 and alpha ≥ 0.1.
- `active` = frontmost app is Claude **or** Idle Paws itself, so clicking the pet doesn't count as "deactivated".
- **Adaptive polling:** 30 Hz while the window moves or resizes; after 30 stable ticks (~1 s) it drops to 5 Hz. Any change switches back to fast.
- Emits `onChange(window?, active)` only on change.

### 4.6 `InputBarLocator` (Accessibility)

Claude Desktop is Electron/Chromium, so its AX tree mirrors the DOM.
- On attach it sets `AXManualAccessibility = true` on Claude's app element. This makes Chromium build its accessibility tree without VoiceOver. Messaging timeout is 250 ms.
- **Prompt predicate:** `AXTextArea`, width ≥ 200, centre inside the window, and (`AXDescription == "Prompt"` or DOM class `ProseMirror`).
- **Card:** nearest ancestor (≤ 8 levels) whose `AXDOMClassList` has a class starting with `rounded-composer`. This is the visible rounded input card, the nicer floor.
- **Fast path:** check the cached element, or adopt the focused element if it's a prompt.
- **Slow path:** BFS of the focused window, skipping static text, with a 6000-node budget. It picks the **lowest** prompt (the active pane in split views), throttled to once per 300 ms.
- Runs on a serial `axQueue`. `axInFlight` stops overlapping lookups.

**Cost (A1 benchmark, `bench/a1-idle.txt`):** enabling Chromium AX on an idle Claude added **+0.9 pp mean CPU, +1.3 pp p95, +0 MB RSS**. That passes the gate (mean < 2 pp, p95 < 5 pp, RSS < 50 MB). The benchmark runs AB/AB rounds and measures cumulative CPU time across all Claude processes.

### 4.7 `Overlay`

- `NSPanel` with `[.borderless, .nonactivatingPanel]`: it can never become key or main, so it never steals focus from Claude's prompt.
- Transparent and shadowless, `collectionBehavior = canJoinAllSpaces, fullScreenAuxiliary, ignoresCycle`.
- **Z-order:** when Claude is active, level `.floating` + `orderFrontRegardless`. When inactive, level `.normal` ordered directly above Claude's window number, so other apps cover the pet correctly.
- Coordinates: CG (top-left origin) → Cocoa (bottom-left), using the primary screen's height.
- **Click-through:** `ignoresMouseEvents = true` by default. A 60 Hz timer polls `NSEvent.mouseLocation`. If the cursor is inside any **hot rect** reported by JS (pet, paw print, open console), or a drag is in progress (`capture`), the panel accepts mouse events. This avoids per-pixel hit testing.
- `OverlayWebView.acceptsFirstMouse = true`, so the first click acts immediately.
- **Mouse streaming** (only in "Follow me" mode): sends `mouse {x,y,inside}` at most every 50 ms.
- **Bridge:** native → JS uses `evaluateJavaScript("window.PetBus.receive({...})")`, queued until JS posts `ready`. JS → native uses the `webkit.messageHandlers.bridge` handler, wrapped in `WeakMessageHandler` to break the WKWebView retain cycle.
- `isInspectable = true` (macOS 13.3+): debug via Safari → Develop → Idle Paws.

### 4.8 `BrowserPaneOpener` — the "Play" button

Opens a URL in Claude Desktop's browser pane **without a Claude turn**, so it works while Claude is busy. It is blocking and runs on `axQueue`.

1. Requires AX trust and Claude's focused or main window.
2. Find the pane: `AXGroup`, description `Browser`, subrole `AXLandmarkRegion`. If it's missing, press the `AXCheckBox` named `Browser` (toolbar toggle) and poll up to 1.5 s.
3. **Tab reuse:** if an `AXRadioButton` tab title contains `Idle Paws`, select it. Otherwise, if the current tab's `Page URL` field isn't empty, press `New tab` and wait for an empty URL field. This avoids duplicate tabs and never navigates away from the user's page.
4. **Enter URL:** focus the field, ⌘A, type the URL character by character with `CGEvent.keyboardSetUnicodeString` posted **to Claude's PID only** (`postToPid`), then read the value back. If it doesn't match, set `AXValue` directly and verify again.
5. Press Return only once the field holds exactly the URL.
6. On failure, the pet shows a speech bubble: *"Couldn't open the browser pane (reason). Ask Claude 'open game'."*

Failure enum: `notTrusted, noWindow, noToggle, paneDidNotOpen, noNewTabButton, noURLField, urlNotEntered`.

### 4.9 `HTTPServer`

A minimal HTTP/1.1 static server built on raw BSD sockets.
- Binds **loopback only**: `127.0.0.1` and `::1` (`IPV6_V6ONLY`), port 4747 (falls back up to +19).
- **Host-header allowlist** (`localhost:P`, `127.0.0.1:P`, `[::1]:P`) → 403 otherwise. This defends against DNS rebinding.
- GET/HEAD only (405 otherwise). 16 KB header cap (431). 5 s receive timeout.
- **Path traversal guard:** the standardized path must equal the root or start with `root + "/"` (else 404).
- Directories need a trailing slash (301), then serve `index.html`.
- Headers: `Cache-Control: no-cache`, `Connection: close`, `X-Content-Type-Options: nosniff`, explicit MIME map.
- One thread per connection.

### 4.10 Web overlay

**`bridge.js`** creates `window.PetBus` with `on(event, fn)`, `receive({event,data})` and `post(type, payload)`.

**`main.js`** does the wiring, plus:
- **Adaptive frame loop:** `setTimeout` at 33 ms (~30 fps) while moving (`walk, run, chase, carry, drag, fall, hop`, or the ball in flight), otherwise 100 ms (10 fps). `dt` is capped at 0.1 s.
- **Demo mode:** outside WKWebView it fakes an env, so `web/overlay/index.html` can be previewed in any browser.

**Events native → JS:** `env`, `prefs`, `mouse`, `outsideClick`, `notice`, `react`, `command`.
**Messages JS → native:** `ready`, `hot`, `mouseMode`, `prefs`, `openGame`, `log`.

**`pet.js` — `PetWorld`** has the behaviour state machine:

```
           ┌──── timer ───► nextState() weighted:  sit 3 · walk 4 · run 0.8
           │                                       sleep 0.3+3·sleepy · play 0.5
 sit ◄──► blink (15%/0.8s)          sleepy = clamp(awakeSeconds/150, 0, 1)
  │
  ├─► walk/run ──arrive──► sit
  ├─► sleep (15–40s, "z" particles)
  ├─► play → throwBall() → chase ──grab──► carry ──arrive──► happy ──► …
  ├─ click ─► happy (♥ ×3)
  ├─ drag ──► drag ──release──► fall ──land──► sit
  ├─ react('done') ─► hop ──land──► happy  + bubble "Done! · project ✨"
  └─ react('attention') ─► sit + "!" + bubble "Claude needs you · project 👀"
```

- **Physics:** gravity 1800 px/s². The ball uses 0.75 g, bounce restitution 0.55, wall restitution 0.6, and ground friction. Hop velocity is −520 × size factor.
- **Chase:** aims the *mouth* (per-species `mouth` grid coordinates), not the body centre, at the ball. It handles walls and grabs when the ball is grounded and within reach.
- **Follow me mode:** if the mouse moved within the last 6 s and is inside the window, the pet runs when more than 80 px away, walks when 16–80 px away, otherwise sits facing the cursor.
- **Frozen:** while the console is open the pet sits still and the ball is cancelled.
- **Floor changes:** if the floor drops (e.g. the composer grew shorter), the pet `fall`s to it. If the floor rises, the pet snaps to it.
- **Input:** a 260 ms click/double-click disambiguation window and a 4 px drag threshold. Double-click on the pet → console. Double-click on the paw print → show the pet.
- **Rendering:** three `<canvas>` elements (pet, ball, paw), moved with CSS `translate`. The pet canvas is redrawn only when `species:color:pose:frame:scale:dir` changes, and is mirrored for left-facing. Hearts, `z` and `!` particles and the speech bubble are DOM elements.
- **Hot rects:** pet bbox, paw bbox (when hidden), console rect. Reported only when they change.

**`sprites.js`** builds sprites procedurally (no image assets):
- Grid 22×17. Shape primitives (`rect`, `dots`, `legs`, faces) plus automatic 4-neighbour **outlining**.
- `SPECIES = {cat, dog, duck}`. Each has a `label`, poses (`stand`, `sit`, `walk` ×4, `blink`, `happy`, `sleep`, …), a `mouth` point and palettes (cat: orange/claude/gray/black/white; dog: golden/brown/spotty/black; duck: white/duckling/mallard).
- Frames and canvases are cached. `paw()` renders the hidden-state paw print.
- Also loaded by `scripts/make-icon.mjs` in a `vm` sandbox to render the icon.

**`console.js` — `PetConsole`:** a popover anchored above the pet with these controls: throw ball, hide, species, mode (Auto / Follow me), colour swatches (per species), size (S/M/L = scale 2/3/4), speed (0.6/1/1.6) and **▶ Play games**.

**Prefs** are owned by the web layer. Every change is posted to native, which merges it into `prefs.json`. On `ready`, native pushes the stored prefs back. Native itself only reads `hidden`, `floorOffset`, `floorPad` and `axPrompted`.

### 4.11 Games

Each game follows the same pattern:
- `engine.js`: **pure, deterministic logic** (injectable `rand`), ESM, unit tested.
- `ui.js`: DOM, input (keyboard, swipe), and `localStorage` persistence under keys `claude-pets:<game>` (legacy prefix).
- `pause.js`: `pauseOnBlur()` pauses real-time games when the pane loses focus (the user clicks back into Claude) or the tab is hidden. Used by Snake, Tetris, Minesweeper (timer) and Sudoku (timer). 2048 is turn-based and doesn't need it.

| Game | Engine highlights | Tests |
|---|---|---|
| 2048 | 4×4, `slideLine` merge-once, `move` returns `{grid, score, moved}`, 90/10 tile spawn | 9 |
| Sudoku | flat 81 array, `PEERS`, backtracking `solve`, `countSolutions` for unique-solution `generate(difficulty)`, `conflicts` | 7 |
| Minesweeper | easy/medium/hard `LEVELS`, safe first click via `placeMines`, flood `reveal`, `chord`, flags | 9 |
| Snake | grid, no-reverse `turn`, `step`, `placeFood`, speed via `tickMs` | 9 |
| Tetris | 10×20, 7 shapes, 7-bag, rotation with kicks `[0,±1,±2,up]`, ghost, hard/soft drop, `dropMs(level)` capped | 9 |

**Adding a game:** create `web/games/<id>/`, add a thumbnail in `thumbs/`, a card in `games/index.html`, and the id in `GAMES` in `server/index.js` (plus the manifest description).

## 5. Key flows

### 5.1 First launch from Claude Desktop
1. Desktop installs the `.mcpb` and spawns `node server/index.js` with `IDLE_PAWS_CLIENT=desktop`.
2. `keepAlive()` sees Desktop running and no socket → de-quarantines and `open -g IdlePaws.app`.
3. The app binds the socket and HTTP server and shows the AX prompt once.
4. The MCP server connects and sends `hello` (lease).
5. `WindowTracker` finds Claude's window → the overlay is positioned. `InputBarLocator` finds the composer → floor → `env` → the pet appears on the input box.

### 5.2 User clicks "Play games"
`console.js onPlay` → `PetBus.post('openGame')` → `AppController.handleWeb` → `openGame(nil)` → `BrowserPaneOpener.open("http://localhost:4747/")` on `axQueue` → pane toggled, tab reused or created, URL typed, Return. On failure, the pet shows a notice bubble.

### 5.3 User asks Claude "open game"
Claude calls `open_game` → server → `open_game` cmd → URL returned → Claude opens it with its own built-in browser tool (or gives the link).

### 5.4 Claude Code session ends
Claude Code runs the `Stop` hook → `hook.js` → socket `react {kind:"done", project}` → overlay → `world.react` → hop, hearts and bubble. If the pet is hidden, the paw print wiggles instead.

### 5.5 Shutdown
Claude Desktop quits → `didTerminateApplication` → app terminates and unlinks the socket. Or all MCP servers exit → 20 s without a lease → terminate.

## 6. Build, packaging, install

```bash
npm test                         # 43 engine tests (node:test)
scripts/build.sh                 # dist/IdlePaws.app + dist/idle-paws.mcpb
scripts/build.sh --app           # app only
open dist/idle-paws.mcpb         # install in Claude Desktop
node scripts/install-hooks.mjs   # Claude Code reactions (optional)
claude mcp add idle-paws -s user -e IDLE_PAWS_CLIENT=code -- node "<ext dir>/server/index.js"
```

`build.sh` details:
- Uses `swiftc -O` directly (SwiftPM in Command Line Tools is broken on this machine). Target `arm64-apple-macos13.0`. Tries SDKs newest-first until one compiles (or uses `IDLE_PAWS_SDK`).
- Bundle: `Contents/MacOS/IdlePaws`, `Contents/Resources/web`, `AppIcon.icns` (from `icon.png` via `sips` + `iconutil`), and `Info.plist` with `CFBundleIdentifier=dev.idlepaws.overlay` and `LSUIElement=true` (no Dock icon).
- **Code signing:** uses the keychain identity `Claude Pets Dev` (or `IDLE_PAWS_SIGN_ID`). A stable identity keeps the **Accessibility grant valid across rebuilds**. Ad-hoc signing changes the code hash each build, so the grant would have to be redone.
- Packing: stage `manifest.json + server/ + IdlePaws.app + icon.png`, then `npx @anthropic-ai/mcpb validate` and `pack`.
- Installed location: `~/Library/Application Support/Claude/Claude Extensions/local.mcpb.pratyaksha-gupta.idle-paws/`.

## 8. Diagnostics

- `open -n -W dist/IdlePaws.app --args --probe-ax`: dumps every text input in Claude's AX tree, with 5 ancestors (role, subrole, frame, description, DOM id/classes). Used to discover the `Prompt` and `rounded-composer` selectors.
- `--probe-buttons`: dumps buttons, fields, tabs and checkboxes with labels and actions. Used to discover `Browser`, `New tab` and `Page URL`.
- `--ax on|off`: toggles `AXManualAccessibility` (used by the benchmark).
- `scripts/cpu-bench.py --rounds 2 --seconds 60 --label idle`: A1 CPU gate.
- Safari Web Inspector on the overlay; `pet_status` tool for a quick health check.

## 9. Security & privacy

| Surface | Mitigation |
|---|---|
| Accessibility (can read/drive any UI of Claude) | Separate bundle, so the grant is scoped to Idle Paws. It only reads frames/labels of the prompt and browser-pane controls and **never reads prompt text** (no `AXValue` reads on the composer). |
| Synthetic keystrokes | `CGEvent.postToPid(claudePid)` only, never global. Only types the localhost games URL into the `Page URL` field, verified before Return. |
| Control socket | User-private dir, `chmod 600`. Commands are limited to pet UI actions and return a URL; no file or exec surface. |
| HTTP server | Loopback-only bind, Host allowlist (anti DNS-rebinding), GET/HEAD only, path-traversal guard, `nosniff`, serves only `web/games`. |
| Hook | 1 s cap, always exit 0, so it can't block or fail Claude Code. Sends only the event kind and `basename(cwd)`. |
| Quarantine strip | `xattr -dr com.apple.quarantine` on its own bundle only. |

No network egress and no telemetry.

## 11. Known limitations & risks

1. **Brittle UI coupling.** Floor detection and Play depend on Claude Desktop's DOM/AX labels: `Prompt`, `ProseMirror`, `rounded-composer*`, `Browser`, `New tab`, `Page URL`, the `AXLandmarkRegion` subrole and the bundle ID. A Claude UI update can break them. Floor detection then hides the pet (when AX is trusted); Play shows a failure bubble. Use the `--probe-*` flags to re-discover selectors.
2. **macOS arm64 only.** The build target is hard-coded to `arm64-apple-macos13.0`, so there's no Intel or universal build.
3. **Multi-monitor:** CG→Cocoa conversion uses `NSScreen.screens.first` height. That is correct for the standard global coordinate space, but displays arranged above or below the primary one haven't been explicitly tested.
4. **First matching window only.** If Claude has several windows, the tracker uses the first layer-0 window in z-order.
5. **Hooks need the overlay running.** If no MCP server is attached (overlay quit after 20 s), hook reactions are silently dropped.
6. **`install-hooks.mjs` bug:** `fs.copyFileSync(SETTINGS, …)` runs unconditionally, so it throws if `~/.claude/settings.json` doesn't exist yet, even though the read above it handles that case.
7. **Legacy naming:** `claude-pets:*` localStorage keys, `Claude Pets Dev` signing identity, and the `claude-pets` hook marker. Kept on purpose for continuity (saved games, AX grant).
8. **Thread-per-connection** servers are fine for this local, low-concurrency use; not meant for load.
9. **Hand-rolled MCP**: doesn't implement resources or prompts. Fine for 5 tools, but protocol changes must be tracked manually.

## 12. Glossary

- **Floor**: horizontal segment `{y, x0, x1}` in overlay coordinates that the pet stands on.
- **Hot rect**: area where the click-through overlay temporarily accepts mouse events.
- **Lease**: an MCP server's `hello` connection; the app lives while at least one lease exists.
- **A1 benchmark**: measurement of the CPU cost of enabling Chromium's AX tree in Claude Desktop.
- **MCPB**: the Claude Desktop extension bundle format (`manifest.json` + server + assets, zipped).
